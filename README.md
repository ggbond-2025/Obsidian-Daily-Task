# Daily Task · 每日待办
基于 **Obsidian + Tasks + 本地“每日待办视图”插件**的个人任务管理笔记库。用 Markdown 记录每天的安排，通过任务总览、月历 / 周历和周总览追踪进度，支持精确到分钟的截止时间。

[任务总览](总览/任务总览.md) · [使用说明](说明文档/使用说明.md) · [搭建说明](说明文档/搭建说明.md)

## 功能概览
任务保存在本地 Markdown 文件中，普通笔记、模板和插件各自负责内容、页面生成和视图展示。

- **每日计划**：按日期创建笔记，记录重要事项、学习、工作、生活任务和每日总结。
- **任务总览**：集中查看今日任务、待办任务、今日到期、逾期和今日完成；每个分区默认显示 5 条，支持展开与收起。
- **截止日期与时间**：在任务行右键或通过命令面板设置日期、小时和分钟，按设备本地时间判断逾期。
- **月历 / 周历**：查看待完成、已完成和即将截止数量，点击日期打开或创建对应每日笔记。
- **周总览**：以周一至周日为范围自动生成，已有文件不会被覆盖。
- **Tasks 能力复用**：通过 Tasks 完成任务勾选与回写，并使用优先级、重复任务、标签等功能。

## 快速开始
日常使用只需要 Obsidian，不需要安装 Node.js 或启动后端服务。

### 1. 打开笔记库
安装 [Obsidian](https://obsidian.md/download)，在库管理界面选择“打开文件夹为库”，选择本项目根目录 `Daily Task`。复制或下载项目时，请保留 `.obsidian` 目录，插件与配置都在其中。

当前随仓库提供的插件版本及其最低应用要求如下。

| 插件 | 版本 | 最低 Obsidian 版本 |
| --- | --- | --- |
| Tasks（`obsidian-tasks-plugin`） | 8.6.0 | 1.13.1 |
| 每日待办视图（`daily-todo-views`） | 1.5.0 | 1.8.0 |

整套库请使用 **Obsidian 1.13.1 或更高版本**。插件文件已包含在项目中，在“设置 → 第三方插件”确认 Tasks 和“每日待办视图”均已启用；在“设置 → 核心插件”确认“日记”和“模板”已启用。

> [!IMPORTANT]
> 模板和现有页面中的 `obsidian://` 快捷链接使用库名“每日待办”，而当前项目文件夹名是 `Daily Task`。使用前请将这些链接的 `vault` 参数统一改为实际库名；本库名为 `Daily Task` 时，对应 `vault=Daily%20Task`。涉及每日模板、周模板、任务总览、已有周总览及使用说明。调整前可通过核心“日记”命令打开今日笔记，通过“每日待办视图：打开 / 创建本周总览”命令打开周总览，或点击总览日历中的日期。

### 2. 核对基础设置
仓库已提供日记和模板配置，首次使用或迁移后请确认下列项目。

| 位置 | 配置 |
| --- | --- |
| 核心插件 → 日记 | 日期格式 `YYYY-MM-DD`；存放位置 `To do`；模板 `Templates/Daily-Template.md` |
| 核心插件 → 模板 | 模板文件夹 `Templates` |
| Tasks → Global filter | 保持为空，使普通任务行参与识别 |
| Tasks → Set done date on every completed task | 启用，为完成的任务记录 `✅ YYYY-MM-DD` |

不需要启用 Tasks 的 JavaScript 自定义查询。更详细的安装与迁移步骤见[搭建说明](说明文档/搭建说明.md)；其中旧的本机路径请按实际项目位置替换，说明文件实际位于 `说明文档/`。

### 3. 开始记录
打开[任务总览](总览/任务总览.md)，切换到阅读视图，先查看逾期和今日到期任务，再打开今天的每日笔记。可以直接编辑已有笔记，或通过日历点击任意日期创建对应笔记。

在每日笔记中，每行记录一项任务，例如下面三种写法。

```markdown
- [ ] 复习集合框架
- [ ] 提交实验报告 📅 2026-10-21
- [ ] 参加线上会议 📅 2026-10-21 🕒 18:30
```

设置时间时，将光标放在原笔记的任务行，右键选择“设置截止日期与时间”，也可以按 `Ctrl+P` 执行同名命令。时间采用 24 小时制，并放在截止日期后面。

完成后勾选任务，晚上在“今日记录 / 今日总结”补充进展。未完成任务可留在原笔记，通过全局待办或逾期分区继续追踪，不必每天复制。

## 任务与日期规则
**笔记日期决定任务归属，截止日期决定到期状态。** 例如写在 `To do/2026-10-18.md` 的任务属于 10 月 18 日的安排，即使它的截止日期是 10 月 21 日。

### 五个任务分区
全局总览提供以下视角；同一任务可以出现在多个分区，勾选时修改的仍是原笔记中的同一条任务。

| 分区 | 显示内容 |
| --- | --- |
| 今日任务 | 今天每日笔记中的未完成任务，包含已逾期任务 |
| 待办任务 | 所有每日笔记中未完成且未逾期的任务，包含往日无期限任务和未来任务 |
| 今日到期任务 | 今天截止、未完成且尚未到具体截止时间的任务 |
| 逾期任务 | 已过截止日期，或今天已到具体截止时刻的未完成任务 |
| 今日完成 | 完成日期 `✅` 为今天的任务，不要求写在今天的笔记中 |

只有截止日期时，该日全天有效，次日起算逾期；同时设置时间时，到指定分钟就算逾期。没有截止日期的任务不会仅因笔记日期过去而逾期。相关视图按分钟检查，使用设备本地时间；截止功能用于分类与统计，没有系统通知或响铃功能。

### 日历与周总览
日历的三个数字采用不同统计口径。

| 日历统计 | 归类依据 |
| --- | --- |
| 待完成 | 任务所在每日笔记的日期，包含已逾期但未完成的任务 |
| 已完成 | 任务所在每日笔记的日期，与实际完成日期无关 |
| 即将截止 | 跨所有每日笔记，按截止日期统计未完成且尚未到截止时间的任务；只在今天和未来日期显示 |

因此，日历“已完成”和总览“今日完成”数量可以不同，三个日历数字也不应直接相加作为任务总数。空白任务占位不会计入统计，父子任务分别计数。

周总览保存在 `总览/周任务总览/YYYY-MM-DD 周总览.md`，文件名使用该周周一的日期。打开库、进入新的一周、新建或打开每日笔记时，插件会检查并补建对应周文件。

> [!NOTE]
> 周总览的五个分区按来源笔记日期限定在该周七天内，但“今日”“逾期”等判断仍使用当前日期，因此历史周总览不是周末状态快照。底部日历固定显示该周，其中“即将截止”仍跨所有每日笔记统计。

任务笔记请保留 `To do/YYYY-MM-DD.md` 的路径格式，移到其他目录后会退出按此路径限定的汇总与日历统计。重复任务、延期、标签等详细操作见[使用说明](说明文档/使用说明.md)。

## 模板与插件维护
修改笔记或模板无需构建；模板只影响之后新建的文件，已有笔记需单独修改。

| 调整内容 | 维护位置 |
| --- | --- |
| 每日分类、默认任务、总结栏目 | [每日模板](Templates/Daily-Template.md) |
| 新周总览的栏目、查询与说明 | [周模板](Templates/Weekly-Template.md) |
| 全局分区、导航与查询 | [任务总览](总览/任务总览.md) |
| 折叠条数 | `.obsidian/plugins/daily-todo-views/main.source.js` 中的 `PREVIEW_LIMIT` |
| 日期、截止规则与统计 | `.obsidian/plugins/daily-todo-views/core.js` |
| 插件命令、日历与页面交互 | `.obsidian/plugins/daily-todo-views/main.source.js` |
| 视图与弹窗样式 | `.obsidian/plugins/daily-todo-views/styles.css` |

### 构建与单元测试
维护 JavaScript 源码时需要 Node.js。以下命令均在项目根目录执行，不需要安装 npm 依赖。修改 `core.js` 或 `main.source.js` 后先构建，再运行测试。

```powershell
node .obsidian/plugins/daily-todo-views/build.cjs
node --test .obsidian/plugins/daily-todo-views/core.test.cjs .obsidian/plugins/daily-todo-views/deadline.test.cjs .obsidian/plugins/daily-todo-views/main.test.cjs
```

`main.js` 是生成文件，应修改源码后构建。构建完成或修改 CSS 后，重新加载本地插件或重启 Obsidian。单元测试覆盖周范围与跨年日期、任务统计、分钟级截止判断、查询转换，以及通过模拟库接口验证每日 / 周文件创建和不覆盖已有文件。

### 可选浏览器检查
仓库另有两份检查脚本；运行前需要可被 Node.js 解析的 `playwright` 包及 Microsoft Edge，额外依赖没有通过根目录 `package.json` 声明。

- `browser-check.cjs`：在模拟 Obsidian / Tasks 环境中检查列表、日历与截止弹窗，并写入 `test-artifacts/` 截图。
- `native-tasks-check.cjs`：加载随项目提供的 Tasks 包检查查询与日期兼容；还需要将环境变量 `OBSIDIAN_ASAR` 指向已安装 Obsidian 的应用归档。

这些脚本提供局部逻辑和模拟浏览器环境的验证，截图也来自测试夹具。实际库中的插件加载、任务回写和页面呈现仍需在 Obsidian 中确认。

## 常见问题
优先检查阅读视图、插件启用状态、任务路径和库名配置。

| 现象 | 检查方法 |
| --- | --- |
| 总览原样显示 `tasks-fold` 或 `todo-calendar` 代码块 | 切到阅读视图，确认“每日待办视图”已启用；更新插件文件后重启 Obsidian |
| 日历显示 `—` 或索引加载提示 | 等待 Tasks 索引完成；在“设置 → 每日待办视图”查看统计读取状态 |
| 写了任务却没有出现在汇总中 | 检查路径是否为 `To do/YYYY-MM-DD.md`、任务是否有内容、Tasks 全局过滤器是否为空，再核对分区和周范围 |
| 昨天的未完成任务不在“今日任务” | 到全局“待办任务”或“逾期任务”查找；“今日任务”只读今天的笔记 |
| 勾选后没有进入“今日完成” | 检查完成日期设置及任务中的 `✅ YYYY-MM-DD`；启用设置不会补写历史完成日期 |
| 截止时间没有生效 | 使用 `📅 YYYY-MM-DD 🕒 HH:mm`，同时写日期和时间，检查设备时间并等待分钟刷新 |
| 快捷链接打开失败或打开其他库 | 将链接的 `vault` 参数改为实际库名；也可使用核心日记命令、本地插件周总览命令或日历入口 |
| 本周文件没有生成 | 确认周模板存在，并执行“每日待办视图：打开 / 创建本周总览” |

备份或迁移时请复制整个笔记库，包含 `.obsidian`。本地“每日待办视图”插件随项目维护，不会通过社区插件市场自动更新。更多操作和排查步骤见[使用说明](说明文档/使用说明.md)。
